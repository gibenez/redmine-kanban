# Sprint Board visual styling

The interface follows YouTrack's visual hierarchy, not its branding or feature set. Compactness and readability are joint goals: a 14px system-font body, stronger secondary text, 30–32px desktop fields/actions and 44px phone controls. Save space through layout and spacing, not smaller issue subjects. The accepted Ring UI palette, 4px radius and neutral/blue visual language remain the foundation.

## Web references

- [YouTrack board UI](https://www.jetbrains.com/help/youtrack/cloud/agile-board-ui.html): compact toolbar, hairline columns, card ID and summary, assignee and estimation, restrained field indicators.
- [YouTrack board settings](https://www.jetbrains.com/help/youtrack/cloud/agile-board-settings.html): priority-based card color schemes.
- [JetBrains Ring UI tokens](https://github.com/JetBrains/ring-ui/blob/master/src/global/variables.css): system font, 8px spacing unit, neutral surfaces, blue interactive accents.
- Existing [visual-language decision](adr/0001-jetbrains-ring-ui-visual-language.md) and [measured references](../.scratch/sprint-planning/youtrack-visual-reference.md).

## Application

Project and Sprint controls, Sprint state and commitment totals share a compact 42–44px context strip. Autorefresh and Refresh now have visible desktop labels; on phones their accessible names and tooltips remain while labels hide to keep all actions reachable. Autorefresh starts off and uses an accessible pressed state, selected border/background and checkmark when enabled; its tooltip describes the state and next action. Refresh now stays disabled during loads and saves. Both controls and the 24px bottom status bar are hidden on the login screen. The status bar occupies its own flex row rather than overlapping Cards. The visibly labelled Sprint filters form a separate full-width, single-row strip. Controls scroll horizontally when necessary, while results and Clear filters stay visible on desktop/tablet; on phones the whole strip scrolls. A single selection shows its actual name (for example, Assignee: Team Member), multiple selections show a count, and tooltips list all selected names. Selected dropdowns stay highlighted; each has its own Clear action that leaves other filters untouched and returns keyboard focus to its summary. Dropdowns are positioned before they appear, fit above or below their anchor within the viewport, track horizontal scrolling and close if their anchor leaves the control strip. Zero matches replace the numeric count with one explicit empty-state message rather than adding another row. Backlog has its own labelled search and Filters disclosure beneath its Column title; a stronger neutral divider separates this planning source from the status Columns. The Backlog Filters button shows the number of active hidden options and lists them in its tooltip, even with the panel closed. This includes Show closed; the visible search is not counted twice. Clearing search/filters still leaves Show closed unchanged, as before. Cards have clear white/theme surfaces within recessed Columns. Each Swimlane, including its title and children across all status Columns, is framed as one non-draggable group with 4px corners, an 8px gap to the next group, and matching 8px outer insets on the left, right and above the first group (in addition to the scrollbar's clear strip). Status dividers remain inside the group, and the full-height priority bar forms its left edge. Ungrouped receives the same frame without a priority bar. The group scrolls normally; “fixed” means non-draggable, not pinned to the viewport. Child Cards, heading controls and related-issue disclosures remain interactive. The frame and the last Column's content share the same edge, leaving room for native or overlay scrollbars. Each Column scrolls independently while its heading remains visible. Narrow screens keep horizontal scrolling inside the board and context strip, never on the whole page. On phones the masthead wraps into two rows; Sprint filters stay in one horizontally scrollable strip rather than taking several rows away from the board.

Loading and saving operations use a viewport-filling modal overlay with a spinner and accessible loading message, blocking pointer and keyboard interaction even over an open editor. Escape cannot dismiss it. It remains visible through sequential and overlapping blocking operations and clears on completion or failure. Backlog scroll-to-load and page retries are non-blocking exceptions. The overlay uses theme tokens and suppresses spinner animation when reduced motion is requested.

Priority is shown only by the left vertical bars on Backlog Cards and Swimlanes, with no priority badges or extra metadata rows. Both use the same 5px `--priority-bar-width` token. This follows the user's explicit stripe-only preference, superseding the badge treatment described in ADR 0001. The mappings remain: Low / Bassa green, Medium / Media (also Normal / Normale) yellow, High / Alta red, Urgent orange, Immediate rose. English and Italian stock names share colors; unrecognized custom names stay neutral rather than being guessed from IDs. Swimlane bars retain their accessible priority name and tooltip. Status Cards keep neutral borders.

Swimlane tags follow the title with an 8px gap rather than being pushed to the right. Due dates, Tracker and the add action remain right-aligned; long titles and tags can wrap when necessary.

Issue IDs share the subject's first line; medium-weight 14px summaries establish hierarchy without adding a row. Cards retain 8px padding and spacing, followed by one compact assignee/Tracker footer. Long names truncate with their full name in a tooltip. Summaries retain the three-line clamp, tooltip and accessible label. Hover adds border/shadow feedback without moving drag targets or disrupting measured Swimlane heights.

Search and Filter requests keep the last confirmed view visible. A keyed per-Column reconciliation updates only changed Cards, fields, counts and loading text, preserving unchanged nodes, column scroll and keyboard focus. The unmapped-status Column remains present when its Sprint issues are filtered out, so other Columns do not resize. Empty-result messaging does not consume board height. Failed searches retain the previous view with an explicit message and suspend paging until a successful search or refresh.

The signed-in identity is a compact initials avatar (for example GB). Clicking it opens a non-modal account popover with the full name and Sign out action. Escape or clicking outside dismisses it; keyboard activation and focus restoration are supported. Signing out still clears the saved API key and aborts outstanding requests.

The login screen uses direct connection instructions, including where to find the API key, with a labelled password field and explicit local-storage warning. A first-in-order skip link reaches the main content with a visible keyboard focus ring. Search fields have visible labels as well as accessible names. Buttons and fields use consistent focus styling; reduced motion suppresses transitions and the loading logo pulse.

An icon-only Appearance button cycles System (default, monitor icon), Light (sun) and Dark (moon). The tooltip and accessible label state the current mode and next action; Enter and Space work like a native button. A small pre-paint script restores the optional browser preference; System reacts to OS changes. Storage failures do not prevent switching themes. These are presentation preferences only: Redmine queries, permissions, drag-and-drop and planning writes are unchanged.
