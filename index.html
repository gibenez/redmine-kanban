Sprint board · Quick guide

Choose your Sprint
Select a Project and Sprint. Backlog filters never change Sprint Cards, Swimlanes or commitment totals.
Plan and update work
Drag a Backlog parent into the Sprint to open it and add its missing ordinary subtasks at every depth, including closed issues. Descendant statuses and other Sprint memberships stay unchanged. The highlighted Add missing subtasks header button adds missing descendants immediately, without confirmation, overwriting their Sprint with the selected Sprint even when already set. Nested Swimlane-capable issues are skipped but traversed. Move an individual issue to Backlog to remove only the selected Sprint, without resetting status. Use the pencil button on Cards or at the far right of Swimlane headings for keyboard-accessible assignee editing. Swimlane-capable issues also offer Status and Priority dropdowns, a Due date picker and read-only Tag chips; ordinary Card popups stay unchanged. Closed Sprints open the popup read-only.
Create a subtask
Use + Add Subtask at the bottom-left of a Swimlane's New cell, even when empty. Choose a Project within the Product Project hierarchy and an ordinary Card tracker; a sole eligible tracker is selected automatically. The parent, selected Sprint and New status are fixed. Title and Description start blank, Assignee unassigned, and Priority uses Redmine's default. Save creates one child and returns to the board without clearing filters. Cancel creates nothing; dirty drafts require discard confirmation. Closed parents and closed Sprints disable creation. Redmine may require fields this editor does not support; validation errors retain your draft. An uncertain creation disables Save to prevent duplicates: check Redmine before starting another draft.
Search backlog
Search Backlog by subject or exact issue ID, such as #123. Combine Tracker, Assignee and exact Backlog tag filters. Only Swimlane-capable trackers are offered. Clear filters resets these four controls, not Show closed. Scroll each Column independently; Backlog loads more as you scroll.
Filter Sprint Cards
The row below the planning header filters only Sprint Cards, never Backlog or Swimlane headings. Search title substrings ignoring case; digits match an exact ID or title text, while #123 matches only issue #123. Select multiple Projects, Assignees or Priorities: alternatives within each dropdown, combined across controls. Zero-match headings hide while filters are active; clearing restores empty headings. Counts include matching Cards outside displayed statuses, but commitment totals stay unfiltered. Choices come from all Sprint Cards. Search and selections are remembered per Project, server and account, even across reloads; absent saved values remain removable. Each dropdown shows its selected name or count; its Clear button resets only that filter. Clear filters resets this entire row. Planning actions still include eligible hidden descendants.
Collapse the Backlog
Backlog shows Unplanned Swimlane-capable issues in all open statuses; Show closed also includes closed issues. Use the chevron in the Backlog header to collapse it and its filters into a narrow rail. Active filters are retained and indicated by “Filtered”. This browser remembers the collapsed state across projects and Sprints. Collapsed Backlog makes no Backlog-only requests; Sprint loading continues normally. Expanding loads a fresh first page, with Retry if loading fails. Expand Backlog before dragging Cards into it.
Filter by Swimlane Tag
The Sprint Tag dropdown uses tags from planned Swimlane headings, including empty ones. A Card matches its nearest planned heading's tags, never its own or outer ancestors' tags. Names match exactly, including case. Multiple tags are alternatives, combined with the other filters. Ungrouped Cards do not match selected tags; flat mode has no heading tags. Tag choices stay stable while filtering, and selections are remembered and cleared with the Sprint filters.
Reschedule a Swimlane
Use the calendar-arrow button beside Add missing subtasks on an open Swimlane to move its parent and all descendants, closed and non-closed, to another open Sprint, including nested Swimlanes and issues assigned elsewhere. The button is disabled only when the Swimlane parent itself is closed or the source Sprint is not open. The popup lists targets by creation date descending (newest first) and preselects the next chronological Sprint when one exists; otherwise choose manually. Confirm to replace Sprint assignments only, keeping dates, statuses, assignees and Target versions. The board stays on the current Sprint. A failed or uncertain update stops the batch and reports moved, failed and unattempted issues without automatic rollback or retry.
Complete a Swimlane
Closing the last open Card by dragging offers to close its parent separately. All Cards in that selected-Sprint Swimlane count, even when hidden by filters; descendants in other Sprints and nested Swimlanes do not. Choose a workflow-permitted closed status or Not now. The app rechecks completion before closing; cancellation or failure never undoes the Card change. Refreshing does not repeat the offer, and reopening a Card never automatically reopens its parent.
Permissions stay yours
Closed Sprints are read only. Redmine checks your permissions and workflow; changes appear only after they are confirmed. Open an issue ID to view its details in Redmine.
Refresh the Sprint Board
Autorefresh starts off. Toggle it in the top bar to enable periodic polling for this session, or use Refresh now for a one-time update. Returning to the tab still refreshes when polling is off. The Redmine icon pulses while loading. Connection, manual refreshes and saving block interaction until finished; tab-return refreshes and polling do not show an overlay. Backlog-only loading, searching and retries do not block interaction; collapse Backlog to cancel its loading.
