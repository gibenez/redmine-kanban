Sprint board · Quick guide

Choose your Sprint
Select a Project and Sprint. Backlog filters never change Sprint Cards, Swimlanes or commitment totals.
Plan and update work
Drag a Backlog parent into the Sprint to open it and add its missing ordinary subtasks at every depth, including closed issues. Descendant statuses and other Sprint memberships stay unchanged. The highlighted Add missing subtasks header button adds missing descendants immediately, without confirmation. Nested Swimlane-capable issues are skipped but traversed. Move an individual issue to Backlog to remove only the selected Sprint, without resetting status. Use the pencil button for individual keyboard-accessible planning, assignment and estimates.
Search backlog
Search Backlog by subject or exact issue ID, such as #123. Combine Tracker, Assignee and exact Backlog tag filters. Only Swimlane-capable trackers are offered. Clear filters resets these four controls, not Show closed. Scroll each Column independently; Backlog loads more as you scroll.
Filter Sprint Cards
The row below the planning header filters only Sprint Cards, never Backlog or Swimlane headings. Search title substrings ignoring case; digits match an exact ID or title text, while #123 matches only issue #123. Select multiple Projects, Assignees or Priorities: alternatives within each dropdown, combined across controls. Zero-match headings hide while filters are active; clearing restores empty headings. Counts include matching Cards outside displayed statuses, but commitment totals stay unfiltered. Choices come from all Sprint Cards. Search and selections are remembered per Project, server and account, even across reloads; absent saved values remain removable. Clear filters resets this row only. Planning actions still include eligible hidden descendants.
Widen the Backlog
Backlog shows Unplanned Swimlane-capable issues in all open statuses; Show closed also includes closed issues. Use the chevron in the Backlog header to collapse it and its filters into a narrow rail. Active filters are retained and indicated by “Filtered”. This browser remembers the collapsed state across projects and Sprints. Collapsed Backlog makes no Backlog-only requests; Sprint loading continues normally. Expanding loads a fresh first page, with Retry if loading fails. Expand Backlog before dragging Cards into it.
Filter by Swimlane Tag
The Sprint Tag dropdown uses tags from planned Swimlane headings, including empty ones. A Card matches its nearest planned heading's tags, never its own or outer ancestors' tags. Names match exactly, including case. Multiple tags are alternatives, combined with the other filters. Ungrouped Cards do not match selected tags; flat mode has no heading tags. Tag choices stay stable while filtering, and selections are remembered and cleared with the Sprint filters.
Permissions stay yours
Closed Sprints are read only. Redmine checks your permissions and workflow; changes appear only after they are confirmed. Open an issue ID to view its details in Redmine.
Refresh the Sprint Board
Autorefresh starts off. Toggle it in the top bar to enable periodic polling for this session, or use Refresh now for a one-time update. Returning to the tab still refreshes when polling is off. Connection, Sprint refreshes and saving block interaction until finished. Backlog-only loading, searching and retries do not; collapse Backlog to cancel its loading.
